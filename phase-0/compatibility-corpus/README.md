# Synthetic FCPXML compatibility corpus

These fixtures were written for Frameline and contain no project or media files from a user. Keep each XML source unchanged after adding it; add a new fixture for a new editor export or behavior. The companion `expected.json` records the read-only v2 scan's observable sequence, clips, media, and warnings. The test checks the source hash separately and validates the full manifest schema.

`basic-edits.fcpxml` covers ordered picture clips, a trim, a move, a gap, and repeated use of one asset. `edit-before.fcpxml` and `edit-after.fcpxml` form a synthetic insertion/deletion pair with a shifted surviving clip. `unsupported-structures.fcpxml` covers a transition, connected audio, an effect, and a nested clip. The expected result deliberately excludes unsupported content and warns about it. These synthetic files are parser coverage, **not** proof that Resolve imports, preserves, or safely writes these structures.

`resolve-structure-live.fcpxmld/Info.fcpxml` is an untouched FCPXML 1.10 export from **DaVinci Resolve Free 21.1.2.10**. It came from the disposable `Frameline Structure Coverage 00 Copy` timeline inside the named `Frameline API Relink Test` project. The media is generated by `generate-moving-media.swift`, `generate-tone.py`, and `mux-moving-media.swift`; `moving-bars-with-audio.mov` is the resulting three-second, 24 fps moving picture with mono audio. The generated movie is ignored by Git and can be regenerated locally. The source has no user footage. The Lua-console readout is transcribed in `live-structure-api.json`.

The API enumerated three video tracks and two audio tracks. It reported seven top-level items: three ordinary video clips, one Cross Dissolve transition, one compound clip, and two audio clips (the compound replaces its two constituent clips at the top level). The first video/audio pair linked to each other; the first video item had one OFX Transform effect. Resolve accepted a requested 12-frame transition but reported and exported a two-frame transition because the adjacent source sections had no handles. The API does not expose the compound's internal items through the parent timeline's track list.

The FCPXML export contains the moving asset, the base `asset-clip` with audio source metadata, a `transition`, a nested `media` sequence referenced by `ref-clip`, and extra video/audio lanes inside a `gap`. The OFX Transform applied through the API was **not explicitly serialized as a filter** in this export; the primary clip has only an `adjust-transform` element with default parameters. This is an observed serialization result, not proof that all effects are omitted. The scanner reads one primary picture clip and reports two warnings: nested clip content is not scanned, and content attached to a gap (including the extra tracks) is not scanned. It does not enumerate the other six top-level items. The scanner remains read-only and does not claim clip identity or safe apply.

The first trial timeline used Resolve's default 01:00:00:00 start while items were appended at record frame 0. Its `Export` call returned true but produced an empty spine. The final timeline was created with `00:00:00:00` and exported at 241 frames. This matters for API fixture generation: a successful export return value is insufficient; inspect the XML content and timeline bounds.

To regenerate the media on macOS, run `swift generate-moving-media.swift moving-bars.mov`, `python3 generate-tone.py tone.wav`, then `swift mux-moving-media.swift moving-bars.mov tone.wav moving-bars-with-audio.mov` from this directory. Resolve import, track construction, and FCPXML export still require the named disposable project. The corpus still needs intended-user projects and exports from other proposed editor editions and versions before a support range can be declared.
