# Experimental rename guard including item-state reads

`prepare-item-state-rename-proof.js` is a separate, opt-in contract for the existing 50-item disposable fixture. It changes no ordinary Apply flow, existing trial schema, historical generator, or shared Lua capture module. It is experimental and always reports `safeToApply: false`.

The write target is the exact API project, timeline, and timeline-item UUID. The project name, item name, count, track layout, inspector dictionary, track state, effect summaries and seven-field supplement are source assertions. Names, positions and media-pool IDs do not select a mutation target. This contract requires Color page, the explicit graph-before-item-state read recipe, and captured status for every supplemental read family and inspector-property read on all 50 items, and available boolean enabled/locked reads for all five tracks; missing dictionary keys remain unknown.

Preparation accepts an enabled original baseline, an independently verified native project export with an expected SHA-256, and the current source observations. Rename changes one item's name to `Frameline item-state guarded rename proof`. Rollback is prepared separately from the actual renamed observations and a fresh export of that renamed source. It restores the original name. Rollback also requires the successful predecessor preparation. Its actual output observation hashes must match the supplied current sources, and its post-state native export hash must match the rollback backup hash. The original backup cannot substitute for that fresh export.

Each phase checks the complete richer observation and supplement, including page/order context, before writing an exclusive started marker and reading it back. It then checks the complete source again immediately before the setter. After the setter, after Save, after Close/Load, and after a fresh post-state Export, it requires the exact expected richer observation and supplement. The only allowed represented change is the requested name. The final output includes independently retained rich and seven-field observations, a result envelope, and a completion marker. The post-state native export backs the next independently prepared phase.

A started marker or any output prevents replay, including after the Lua session restarts. No path is deleted or reused by an issued command. Failures retain source files, native backup, started marker and any partial outputs. Host inspection reports `preflight-rejected` before the started barrier, `recovery-required` after it, and also `recovery-required` when a started operation has incomplete outputs. It never retries a setter, clears the marker, or automatically repairs a failed operation. A failed setter can have changed state even when it returns false. Recovery requires fresh inspection and a separately prepared restoration from an exact recognized source; unexpected represented state must be resolved independently.

The host checks private canonical directories, regular owned singly linked files, bounded reads, source reconstruction, source hashes, native archive structure/hash, exact envelope keys, rich and supplemental equality, and nonce-bound markers. The runtime verifies backup presence and size, rather than its archive hash. The native export/source association is a host receipt, not a proof that opaque native graph contents equal a represented capture. Readback barriers do not prove power-loss durability, atomic filesystem publication, or atomic editor capture.

Run `node --test tests/item-state-rename-proof.test.js`. Six tests execute actual generated Lua with the installed vendor library. They cover independent changes to all seven read families, zero setters for stale sources, post-barrier drift, hidden drift after the setter and after reopen, successful rename/rollback, replay, save failure, retained interrupted output and host path/source/backup safeguards. Mock execution does not establish native availability or full preservation.

General lossless preservation remains unproven: variable retime, inherited timeline blanking values, full Fusion and color graphs, nested content, arbitrary effect parameters, multiple color layers and opaque native fields are outside this capture. This experiment extends the represented guard only; it cannot close the overall preservation gate.

## Native result

The parent invoked a fresh read-only source capture, the separately prepared rename, and its independently prepared rollback on the installed Resolve Free build. All 50 items had captured status for all seven supplemental families; all 1,600 returned inspector properties and five track states were available. Every source and result checkpoint passed. The renamed output contains exactly the requested name delta and zero supplemental-field deltas. Rollback restored the original richer observation and seven-field observation byte for byte. The renamed native export backed rollback through the enforced predecessor hash chain; its source was not inferred from a file name or track index.

`phase-0/item-state-rename-evidence/` retains the raw envelopes/barriers and compressed original, renamed and restored observations. `auditItemStateRenameEvidence()` in `phase-0/item-state-rename-evidence.js` recomputes their independently pinned hashes, exact source map, expected represented changes, output markers and fresh-backup chain. Its `readOnly: true` describes the pure host audit; the live proof performed two SetName/Save/Close/Load/Export sequences and is explicitly `readOnly: false`. Stale hidden-state refusal, replay and interrupted failure behavior are generated-Lua mock evidence rather than extra native mutations.

The three installed Utility scripts were removed after exact source/hash/owner/link/inode verification. Forty private evidence/source files across three preparation directories, including four native backups and five Lua programs, are retained under the gitignored `phase-0/private-integration-proof/item-state-rename/` with directories0700/files0600. The manifest verifies every byte count and SHA-256; original preparations remain unchanged. These copies are inspection records and must not be replayed. Distinct native export hashes are retained; represented restoration does not imply native archive byte equality or full native semantic preservation.
