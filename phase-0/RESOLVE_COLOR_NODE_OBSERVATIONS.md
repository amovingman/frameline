# First-layer color node-slot reads

This separate read-only supplement captures `Graph.GetToolsInNode(index)`, `GetNodeColor(index)` and `GetNodeCacheMode(index)` for each slot from 1 through the returned `GetNumNodes()`. It extends the earlier count-only observation without changing that format or its historical source. The installed, pinned `DaVinciResolveScript.pyi` SHA-256 is `2a6c156fcba727b73e16fdc21b90e77db9b914c08c5bf5b53b584380a972f8d7`.

That reference documents no graph-node unique ID, connection accessor or complete typed node-object enumeration. Its `FusionComp` is an empty declaration, so it does not provide a documented Fusion tool/connection surface here. Node positions remain capture-local, one-based indexes. The output explicitly says `topologyObserved: false`, `persistentNodeIdsObserved: false` and `completeGraphObserved: false`. This cannot close complete enumeration, identity or preservation gates.

The supplement omits labels and LUT reads, which could expose user text or paths. Returned tools are retained as ordered bounded identifier tokens, not interpreted as effect-instance IDs or complete parameters. Tokens must match `[A-Za-z_][A-Za-z0-9_.-]*` and fit 128 bytes; an unexpected spelling rejects the capture rather than being omitted or replaced. A captured empty list and unavailable getter remain distinct. Node color follows the SDK's literal list, including the captured empty string. Cache mode preserves the documented integer without guessing the numeric mapping to `resolve.CACHE_*` constants.

`src/companion/resolve-color-nodes.lua` reads only the first clip layer, and only when already on Color. It never switches pages, selects a timeline or changes a project. A project-wide preflight refuses more than 200 items, 20 timelines or 200 tracks before the expensive base capture. Per-graph and total limits are 256 and 2,048 nodes. Both full supplemental reads must match, node counts are rechecked within each graph, and the schema-3 snapshot, page and active timeline must match across the reads. This is a consistency check of represented data, not an atomicity or absence-of-getter-side-effects guarantee.

The menu preparer additionally pins the known 50-item disposable fixture UUID, exact installed build and complete supplied richer baseline. Rich captures must match before and after the node-slot reads. Its actual source is reconstructed at host readback; private outputs require exact writer readback, a nonce-bound completion marker, owned single-link regular files and canonical directory ancestry before permissions are tightened. Only static failure codes leave the runtime.

```sh

Mock results are not native editor proof.

## Separate cosmetic annotation challenge

`prepare-color-node-challenge.js` and `resolve-color-node-challenge.lua` implement separately issued `color` and `restore` phases on the exact disposable fixture and first item UUID. Each phase requires the original rich, seven-field and node-slot observations. The selected first-layer graph must have exactly one node and the original color must be the captured empty string. The sole supported setter is `Graph.SetNodeColor(1, 'Blue')`, followed in the separately prepared restoration by `SetNodeColor(1, '')`. This changes cosmetic node UI annotation, **not image-grading parameters**. Slot 1 is unambiguous only in that exact one-node source state; it acquires no persistent identity.

Every rich property/track read, all seven supplemental item-state families, and each returned node color/cache value must be captured in the supplied baseline. The three source contracts are compared before publishing a started marker and again immediately before the setter. The target's API item UUID, timeline UUID, name, single-node count, original color and exact signed cache mode are checked again on the graph used for the setter. After the setter, save, close/reopen and native export, all three contracts must match, allowing only the selected node-slot color change. Unavailable tool reads stay unavailable and never imply preserved tool contents.

Preparation verifies and privately copies the supplied native backup by content hash and archive integrity. The runtime checks that retained backup's presence and size; neither check proves native semantic equivalence. Successful output retains a fresh post-state native export. Restoration requires the successful color phase's actual raw rich/extra/node outputs, exact rendered-source binding and verified fresh export hash through its predecessor receipt. Restoration is issued separately after host verification. A started but incomplete or divergent phase remains `recovery-required`; the script does not blindly restore a source that diverges. Started/readback markers prevent ordinary replay but do not establish power-loss durability.

`tests/color-node-challenge.test.js` executes both generated phases in vendor Lua mocks and verifies the actual host predecessor/backup reader. It checks same-count change detection, all three stale-source guards, drift after the started barrier, replay refusal, post-write/reopen divergence, save failure, incomplete output recovery, altered sources/backups, hardlinks and directory aliases. Mock success does not establish a successful native annotation change or grade preservation.

Both separately invoked native phases subsequently completed. The selected node's cosmetic color changed from the empty string to `Blue`, survived save/close/reopen, and was separately restored to the empty string. Every node count stayed unchanged. Both phases returned the exact original 1,600-property rich observation and seven-field observation bytes. Tools remained unavailable. This closes a same-count cosmetic annotation read/guard gap, not grading-parameter preservation or complete graph enumeration.

For each native phase, the first host read happened while that same invocation was still publishing output and conservatively returned incomplete. A later read verified completion without another UI invocation or command replay. Incomplete retained output is neither a completed outcome nor proof that an active invocation failed; it must not cause replay. If the invocation terminates or the state diverges, retain the backup and inspect the project before separately reviewing recovery.
