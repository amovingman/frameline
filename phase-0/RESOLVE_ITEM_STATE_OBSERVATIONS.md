# Additional read-only item-state observations

This separate opt-in schema-1 supplement records documented `TimelineItem` reads missing from both the schema-3 snapshot and the returned inspector-property dictionary: clip enabled state; returned speed options; fade durations; output blanking and its timeline-inheritance flag; Fusion composition count; and the first color-layer node count. It does not change the existing observation/revision schemas or authorize editor writes.

The exact installed `DaVinciResolveScript.pyi` reference, SHA-256 `2a6c156fcba727b73e16fdc21b90e77db9b914c08c5bf5b53b584380a972f8d7`, declares the corresponding methods and the `SpeedOptions`, `FadeInfo` and `OutputBlanking` dictionaries. These declarations establish which reads to attempt, not runtime availability or full editor state coverage.

## Capture contract

`src/companion/resolve-item-state.lua` exports `capture(resolve, base, encode, maxItems)`. `base` is the existing schema-3 module with `capture`, `encode` and `array` exported, and `encode` is the existing effect supplement's JSON encoder. The default Console builder uses a 50-item bound; the maximum is 200, across at most 20 timelines and 200 tracks. A preflight counts every track before the expensive base capture, and an oversized project is refused rather than truncated. Use a small disposable project, not a subset masquerading as a complete project snapshot.

Each read has `{ "status": "captured", "value": ... }` or `{ "status": "unavailable", "value": null }`. An API exception or nil read is unavailable. A returned dictionary may omit documented keys, including being empty; missing keys have unknown applicability and are never filled with false, zero or other defaults. Unknown dictionary keys and malformed types fail capture rather than being silently dropped. The Lua bridge's non-domain `__flags` entry is omitted.

Speed percentage preserves the Lua runtime's 17-significant-digit scientific decimal text. Other returned speed fields are booleans. Fade and blanking fields retain integer frame/pixel values. The timeline's own blanking pixel values remain unobserved when an item inherits them. Counts are nonnegative integers. A nil color graph is unavailable, not zero nodes. `GetNodeGraph()` reads only the first layer, exactly as documented; no graph contents, LUT paths or node labels are collected. Composition count similarly does not enumerate Fusion graph contents.

The complete supplement is read twice and must match, followed by a repeated schema-3 capture and active-timeline ID check. The current editor page is recorded and must also remain stable. This rejects represented concurrent changes, including changes invisible to schema 3. Two equal reads still do not guarantee an atomic snapshot or preserve unobserved state. No project save, load, timeline selection or project-mutation call occurs.

An initial native attempt on the new 50-item fixture failed with the original generic `state-changed` code and produced no accepted observation. The parent observed the UI navigate from Edit to Color while the getter-based capture ran. The retained failure does not identify which of the original combined checks diverged, so no successful state-preservation claim is made for that attempt. The current reader policy invokes `GetNodeGraph()` only if capture starts on Color; other pages explicitly leave its count unavailable. A page change during capture rejects the observation. Distinct failure codes now identify supplemental-read, expected-snapshot, snapshot-context, timeline-context and page-context divergence. Getter naming does not establish an absence of UI side effects, and first-layer counts still do not prove graph contents unchanged.

A second native attempt on Color also rejected the two supplementary reads. A separate diagnostic retained both raw typed readings without accepting a stable observation. It found exactly 98 differences: 49 items changed from unavailable to captured empty `outputBlanking` dictionaries, and the same 49 changed from unavailable to captured `usesTimelineOutputBlanking: true`. The other five fields, schema-3 state, page, active timeline and complete richer observation matched. This demonstrates a read-context dependency; it does not establish that unavailable values mean empty/true or that getter calls preserve opaque native fields.

The earlier page-aware, item-first source is retained untouched at `phase-0/item-state-history/page-aware-before-order.lua`, SHA-256 `346d53684759a694fb3193be49407e43768d00d2b3cc20906ac15f3fd6043132`. The new, explicit `readOrderPolicy: "color-graph-before-item-state"` acquires the first color graph/count before the other getters when already on Color. It still skips graph reads on Edit/other pages. This is a separately recorded recipe with a deterministic dependency mock: blanking remains unavailable until graph acquisition, the old order yields the 49-item divergence, and the new order gives matching typed reads. A fresh native capture verified that recipe on all 50 items: all seven field families were captured twice with matching typed values. Only speed `Percentage` and both fade keys were returned; the blanking dictionary was empty with timeline inheritance true. Missing keys remain unknown. No automatic warm-up retry was performed.

## JavaScript and transport

`src/resolve-item-state-observation.js` exports strict validation, parsing, per-read/per-key coverage, and paired comparison. Exactly one record must match every snapshot item by timeline/item API ID. Foreign items, duplicates, malformed values, getters, unknown fields, unknown versions and path-bearing snapshot metadata are rejected. Comparisons preserve exact source hashes and report additional-state changes separately from schema-3 changes. Decimal comparison uses the existing exact semantic normalizer. `safeToApply` and `losslessRoundTripProven` remain false.

`createItemStateCaptureCommand(projectName, {maxItems: 50})` in `src/resolve-item-state-console.js` builds an explicitly named-project, exact-version read-only Lua Console command. Its ordered 8-KiB parts are bound to a random capture ID and a 2-MiB result limit. `readItemStateConsoleResult` validates the assembled observation. The module can also be embedded by a separately reviewed menu handoff; it has no file writer of its own.

Run `node --test tests/resolve-item-state-observation.test.js`. Tests execute the actual generated source in the installed vendor Lua library against a mock, including hidden-state divergence, unknown returned keys, unavailable reads, count-before-capture refusal, and transport/host validation. A successful mock is not native editor evidence.

## Remaining proof

The controlled capture/change/save/reopen/restoration experiment now passes on this fixture. The supplement still needs integration into any broader experimental write guard before that guard can claim additional-state coverage; the existing rename guard is unchanged. Unknown key applicability, variable-retime keyframes, arbitrary effect parameters, complete Fusion/color graphs, nested contents, multiple color layers and opaque native fields remain unobserved. The lossless-fields roadmap checkbox remains open.
