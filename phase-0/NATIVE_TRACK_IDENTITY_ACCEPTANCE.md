# Finite acceptance for the personal Resolve identity gate

The original task is to identify clip and track IDs and test their persistence after rename, move and save. It does not require a release range, FCPXML occurrence mapping, cross-device behavior or complete field preservation. Direct API writes locate clips by API project/timeline/item UUID. Names, media-pool IDs and positions validate context and never replace that namespace.

The installed primary SDK documents project, timeline and item unique IDs, current track enumeration, `GetTrackTypeAndIndex`, `GetPosition`, name setters and `MoveItems`. It provides no persistent track UUID accessor. Untouched native archives expose explicit `Sm2TiTrack.DbId` identities with project/timeline/sequence/container parentage. The exact-build per-kind vector index locates the current API slot; it is an empirically tested location rule, not the track identity.

`native-track-identity-acceptance.js` is separate from historical proofs and the generic low-level mapper. Its diagnostic shape validator `requireSupportedIdentityProfile(graph, observation, apiWitnesses)` requires actual captured Free product/version/IsStudio-false runtime reads, both independent API location getters for every video/audio item, complete represented inspector/track reads, and exact witness/source context. It rejects transitions, subtitle tracks, unknown structures and uncalibrated native track profiles. The finite profile is normal flat video (native Type0/SubType0/Flags0) and mono audio (Type1/SubType1/Flags0) on API build21.1.2.10. It performs no editor mutation. Its output is `observedIdentityShapeValidated: true`, `supportedIdentityProfileValidated: false`, `savedCheckpointRequired: true` and `currentUnsavedStateBindingProven: false`. A synchronized API/export interval alone cannot prove live empty-track identity: the interrupted native experiment retained the prior saved identity graph in exports made after unsaved topology changes. Operational supported mapping therefore requires the separate source-bound saved/reopened checkpoint readers. A retained checkpoint identifies that saved state; it does not identify a later unsaved empty-track replacement. The shape validator never enables Apply or claims persistence from one read.

The finite native acceptance consists of three withheld fresh-identity cases: a new4V4A project with50video and2audio occurrences; a retained-UUID clip rename/move plus empty-track append/delete that shifts retained track indexes; and replacement of a known empty track at the same current slot and name with a fresh native UUID. Every case must freeze its full prediction before an independently issued unique-name challenge. The challenge native source verifies the exact frozen prediction bytes before its first setter and echoes both the raw-file and canonical-object hashes. Its source-bound result records save/reopen and restoration. The acceptance validator alone does not establish execution order or power-loss durability.

`validateBlindTrackBindingCase` recomputes synchronized current bindings, requires fresh project/timeline/sequence/container/track IDs disjoint from every old calibration graph, requires populated video and audio witnesses and at least two duplicate-name empty tracks in each kind, and verifies both prediction hashes. It independently finds challenge responses by the native hash of each unique API nonce name. That witness deliberately ignores vector ordinals. All predicted UUIDs must agree, including empty tracks. Challenge and restoration must retain the complete native identity/parentage/member graph; represented API state must restore exactly. Unknown native-field preservation is a separate requirement, not inferred from identity continuity.

The recorded prediction format is UTF-8 canonical JSON with one trailing LF. `predictionSha256` and `challengePredictionSha256` name the exact file bytes; `predictionCanonicalSha256` and `challengePredictionCanonicalSha256` name the canonical object without LF. Both pairs must match. `loadIndependentIdentityCalibrationGraphs()` first recomputes the pinned old calibration audit, then collects all12 historical before/challenged/restored graphs. That ledger is used only to exclude old IDs from the withheld fixture; the generic mapper never imports it.

`validateIdentityPersistenceTransition` requires the same project/timeline/sequence/container namespace, all clip UUIDs retained, one requested clip name change and one native-parent move, one known empty-track deletion and fresh empty-track creation, and a retained track UUID with a changed current index. It refuses collateral represented item/property changes. `validateNativeTrackTopologyStage` also supports separately retained append-empty, delete-empty and replace-empty states, with exact UUID deltas, empty-track witnesses, expected index shifts and the complete retained clip-ID set. `requireNoTrackIdentityResurrection` additionally rejects a recreated UUID observed in any earlier case, including an identity already deleted before the immediately preceding graph (the ABA control). Parent harness provenance must link those states and record their actual supported API calls and save/reopen/export events.

`selectApiOccurrence` demonstrates the direct API locator even when names, frames, media IDs and item UUIDs collide in another timeline. It requires the exact project and timeline namespace and reports `writeAuthorized: false`; mutation authorization still requires the separately reviewed full-source/result/backup/replay guards.

Thirteen independent tests in `tests/native-track-identity-acceptance.test.js` cover the finite criteria and negative controls. A consistently swapped empty-track ordinal hypothesis fails the independent name witness even if the recorded prediction and all supplied source graphs agree with that wrong hypothesis. Other controls reject unavailable getters, Studio runtime, foreign witness context, transitions/subtitles, uncalibrated flags/subtypes, old calibrated IDs, cross-namespace UUID correlation, reused recreation IDs and collateral clip changes. They also verify separate topology stages and exact field comparison by namespaced item UUID when a move changes native enumeration order. Native harness evidence remains necessary in addition to these tests.


## Native closure result

All three native blind challenges passed on the fresh52-item4V4A fixture. The independent validator recomputes24 API-location/native-UUID associations over10 distinct observed native track IDs, including five empty tracks initially and four in each later case. Both API location getters cover all52 items in every case and confirm the actual Free runtime. All52 clip UUIDs persist through the supported clip rename/move and save/reopen checkpoints. Seven initial track UUIDs persist through the earlier empty-track deletion, and two retain their IDs at new indexes. The known empty currentV4 is then recreated at the same index/name with a UUID absent from all nine earlier observed track IDs.

The original composite stage remains interrupted: its expected post-move arrays used the earlier enumeration order. An independent read-only diagnostic proves strict equality of every represented value after sorting only identity-keyed snapshot/item collections. A separately guarded continuation saves, closes and reopens that exact inspected source without repeating prior mutators. The three original before-save exports retain the previous saved identity graph, rather than the intended intermediate topology. They remain diagnostics and never become mutation or current-unsaved binding evidence. The supported workflow consequently accepts only source-bound saved/reopened checkpoints.

The pure `auditNativeBlindIdentityEvidence()` in `native-blind-identity-evidence-audit.js` verifies25 retained public raw/fact/prediction/marker artifacts,21 source hashes, the nonce prediction readback/main-path sequencing, all three independent cases, strict order-only diagnosis, separate save/reopen continuation, UUID persistence and full-history ABA control. Its `stableClipIdentityProven` and `stableTrackIdentityProven` apply only to the declared personal saved-checkpoint scope. It explicitly reports `currentUnsavedStateBindingProven: false`, `ordinaryApplySupported: false` and `fullNativePreservationProven: false`. Five closure tests reject raw/source/receipt tampering and invented interrupted-stage success.
