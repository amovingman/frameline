# Read-only native database preservation evidence

This separate experiment tests the disposable project's persisted SQLite values without treating DRP export serialization changes as harmless. No SQL write connection opens the live Resolve database. Ordinary Apply remains disabled.

The native source must first be saved and closed through a source-verified companion contract. Resolve may leave an empty unsaved placeholder rather than returning nil from `GetCurrentProject`; a separate typed, two-pass source-absence diagnostic admits only the measured placeholder and retains the original failed nil assertion. A snapshot record links the recognized close/absence result. The database reader does not independently prove that native execution occurred, and its flags say so.

The Python reader copies the source with a read-only, nonblocking, no-follow file descriptor. It requires a canonical, owned, single-link regular file; absence of journal, WAL and SHM files; unchanged inode, size, modification/change times and exact bytes across copying. For actual project evidence, `requireSingleProjectDirectory: true` additionally requires a directory named for the expected project containing only its regular `Project.db`, with an unchanged hashed directory manifest. Output lives outside that directory in a private directory. Raw snapshot, census and record files are exclusive, directory-descriptor-anchored publications at 0600, with readback and fsync. Source files are not chmodded or written.

SQLite opens **only the private copy**, using `mode=ro&immutable=1`, `query_only` and disabled extension loading where exposed. It requires UTF-8, rollback/delete journal format and a successful integrity check. Immutable mode is appropriate only for that verified copy; it is not used to assume a live file is static. SQLite documents [read-only URI parameters](https://sqlite.org/uri.html), [consistent snapshot requirements](https://sqlite.org/backup.html), and the fact that hot journals/WAL [are part of database state](https://sqlite.org/fileformat.html).

The private census covers every `sqlite_schema` object and rowid, every persistent table including SQLite internal tables, complete `table_xinfo` including hidden/generated columns, every rowid where accessible, primary-key binding and every cell. Rows are sorted without deduplication. Virtual/shadow tables and inaccessible rowids refuse. Values retain SQLite storage classes: exact integer decimal values, REAL IEEE754 bit patterns, raw TEXT bytes, raw BLOB bytes and NULL. Text bytes are not normalized, decoded into guessed native semantics or coerced to BLOB. All unknown columns remain covered. Raw database bytes preserve the physical SQLite representation separately.

`readNativeSqliteSnapshot(recordPath)` rehashes the raw database and recomputes the complete census before returning verified facts. `compareNativeSqliteSnapshots` performs that verification for both inputs, then compares all schema objects, table metadata, row identities/multiplicity and values. It may authorize exactly one stale-checked `Sm2TiItem.Name` cell bound to the declared primary-key UUID. Any other cell, row, table, schema or application-pragma change fails. No column is labelled volatile or excluded. Diagnostics contain value hashes and bounded row/cell locations, not native values or local paths.

The pure comparison also validates census structure, duplicate table names, row identities, column/key coverage and counts, so supplied records cannot hide fields through map-key collisions. The comparison remains a supplied-evidence result: actual native execution, API target parentage and closed-checkpoint chronology require their separate source-bound receipts. No database census or byte comparison alone promotes `losslessValidated`.

Four JavaScript tests run ten Python cases and verify private publication, whole-source nonmutation, unknown binary/text cells, int64/REAL values, internal and generated columns, row multiplicity, composite keys, schema changes, inaccessible rowids, virtual tables, source aliases/links/FIFOs, sidecars, forged duplicate records, raw/census tampering and the exact one-cell edit.
