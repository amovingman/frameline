# Safe-pull preflight foundations

These are ten local safety slices for the Free 21.1.2 experiment. They do not make a pull executable.

1. Stream media files through SHA-256 without loading them into memory.
2. Report local, missing, and unknown media; offline-volume, proxy-only, and excluded require explicit evidence.
3. Search a user-selected folder with limits and without following observed symlinks.
4. Verify candidate media by file size and SHA-256, not name alone.
5. Produce a path-free readiness report that requires verified originals for required media.
6. Reserve a noncolliding `.fcpxml` review-copy filename in a selected directory.
7. Make a byte-verified review copy while preserving ordinary mode and timestamps.
8. Confirm the source hash and file identity again before publishing the copy.
9. Remove incomplete temporary copies after a failed preparation.
10. Run a read-only apply preflight that reports missing plan, audit, media, source, restore-point, or adapter gates.

For local experiments, `check-media-readiness.js` reads an array of media entries containing opaque `id`, local `path`, and expected `{size, sha256}`. The report omits all paths. `prepare-review-copy.js` requires the current source hash and creates a byte-identical copy; it does not apply a plan:

```sh
node phase-0/check-media-readiness.js media-input.json
node phase-0/prepare-review-copy.js source.fcpxml copies Review.fcpxml EXPECTED_SHA256
```

The review-copy helper accepts regular `.fcpxml` files up to the scanner's 20 MB limit; bundles and symlink path components are refused. `checkApplyPreflight` is a main-process diagnostic only. The current Resolve API snapshots cannot authenticate a project file, media requirements are not bound to verified file paths, and the FCPXML adapter lacks safe apply and editor validation. It therefore always returns `safeToApply: false`. No project file is modified by these preflights.

### Version-2 command guards and conservative recovery

Version-2 Console-issued records use `recoveryVersion: 2`; current desktop retained-file issuance uses version 3 as described below. Before accessing the project manager or capturing project state, a copied forward command requires exact retained `issued.json` bytes. Recovery commands additionally verify the original issuance, retirement barrier, inspected observation, and issued recovery action. An existing partial/final result or a retired command is refused. Node validates exact issued fields/mode and rechecks the native archive receipt at issue/read/save; the command's retained-record guard does not rehash the archive at the instant of mutation.

The byte reader uses `resolve:Fusion():OpenFile(filename, 1)`, exact file sizes before/after, bounded positive-progress `ReadLine()` chunks, exact UTF-8 bytes, nil EOF, and a successful standalone `Close()` call. No Lua `io` fallback is used. Blackmagic's [Fusion 8 Scripting Guide](https://documents.blackmagicdesign.com/UserManuals/Fusion8_Scripting_Guide.pdf#page=116) documents numeric-mode `OpenFile` and its line-reading example; its [IOClass reference](https://documents.blackmagicdesign.com/UserManuals/Fusion8_Scripting_Guide.pdf#page=147) lists the reader/close methods. The pinned Free build's read-only native probe separately established mode `1`, preserved newline bytes, nil EOF, and a `Close()` with no return values while Console `io` was nil. These empirical details are not inferred from the older guide or from the test runtime.

Recovery permanently retires the original command before inspecting a fresh complete observation. Exact original state offers **Verify saved source**; exact renamed state offers **Restore original name**. Both save/close/reopen and must match the original represented state. Divergence offers no automatic mutation. An unacknowledged successful rename is never silently accepted as applied: explicit recovery returns to the original observed state and records `restored` or `source-verified`. Starting recovery prevents later normal-result acknowledgment. Legacy version-1 non-forced or unguarded records remain manual; they are not upgraded into this capability.

The original twelve emitted-command tests execute the exact generated Lua in fresh installed LuaJIT runtimes with Console `io=nil`, a Fusion-reader filesystem boundary, and separate working/saved fake-editor state. They cover successful acknowledgment, forced rollback, discarded successful output followed by explicit restoration, never-run source verification, stale and divergent state, save/close/load failures, collateral Pan/effect changes, post-issue retained-byte changes, partial outcomes, reader failures/closure, portable audit validation, idempotent history save, and pinned-head races. They do not connect to Resolve. That milestone passed all 796 full-suite tests and 409 security tests, with no failures or skips; packaging validation passed.
