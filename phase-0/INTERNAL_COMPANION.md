# Resolve Free internal companion prototype

DaVinci Resolve Free 21.1.2.10 did not accept the external Python scripting connection in the November 17 probe. The user chose to retain Free and test an internal script companion. The installed build exposes Lua in Workspace → Console. Its Scripts menu discovers `.lua` Utility files, but the menu runtime did not expose the expected file or system clipboard handoff. The desktop therefore uses a **read-only, manual Console handoff** for disposable projects.

## Live result

On November 17, Frameline copied a five-minute, request-bound Lua command to the macOS clipboard. The command ran in Resolve's Lua Console against a new disposable project named `Frameline Lua Capture Fixture`. Copying the Console output back to the clipboard and selecting **Read copied result** in Frameline verified the request ID, request hash, expiry, project name, schema, and normalized snapshot. The live sequence progressed from an empty project to **one timeline and one audio item**. The saved timeline and item retained their API IDs; the item had exact frame positions and media-pool ID. Frameline saved the final verified capture as a local read-only observation revision on `main`.

The clip probe exposed a Lua binding detail: empty `GetEffects` lists include a `__flags` metadata entry. The companion now counts only positive integer list entries. A repeated live capture reported zero effects for the unmodified audio clip and passed the desktop validation loop.

The older ten-timeline performance project produced no usable Console output when the full snapshot was printed. The Lua command now holds responses over 16 KB in a Console variable and prints 8 KB parts on request. Frameline checks the request ID, part order and count, byte limit, then validates the assembled response against the private request. A live disposable timeline with **48 audio items** transferred in three parts and passed desktop validation. Adding two picture items and a Cross Dissolve yielded a second three-part capture of **51 items**, also verified by Frameline and saved as a path-free fixture. The transition's source interval and media-pool ID were null, as returned by the API. A third three-part capture verified **53 items** after adding a linked video/audio clip and one Gaussian Blur OFX; the paired snapshots expose the two new items and the effect-count change. This verifies the larger manual handoff for those fixtures, not arbitrary project scale, complete timeline content coverage, or a safe apply path.

## Desktop flow

1. Open a **disposable project** in Resolve Free. Enter its exact name in Frameline's Resolve preview and choose **Copy capture command**.
2. Open Workspace → Console, select Lua, paste the command, and press Return. The command only reads the open project.
3. Click the Console output, press Cmd+A and Cmd+C, return to Frameline within five minutes, and choose **Read copied result**. For a large capture, Frameline copies the next part command; repeat the Console and clipboard steps until verification finishes. New desktop requests require the richer property/track/effect observation. Capture status exposes counts, unavailable reads and a snapshot hash; complete observations remain in the main process.
4. **Save capture JSON** writes the complete verified property/track/effect observation. **Save snapshot JSON** writes its schema-3 timeline/clip component for older reviews and the separate rename experiment. Both publish a complete, synced file privately without replacing an existing destination. **Save local revision** retains the complete observation under the Resolve API project ID. Local Resolve observations can compare returned clip properties, effect slots and indexed track state after restart. History preview includes richer captures by default; values not observed on all three sides appear as coverage gaps. Clear the include checkbox to select snapshot-only compatibility.

The Console handoff includes display names, opaque IDs and returned property values. It remains on this Mac. The private request stays in Frameline's user-data directory with restrictive permissions. The bundled Lua capture and effect/property reader are copied to an immutable, hash-named private directory. No Resolve project is changed by capture, and neither an observation branch nor a matching project ID proves live edit provenance.

## Normal property history

Desktop capture requests now use protocol version 2, bound to operation `capture-properties`. The response must contain a valid schema-2 observation; an older snapshot-only response cannot satisfy that request. The existing ordered, bounded Console transport carries the new envelope, preserving the five-minute request/hash/project checks. Legacy version-1 requests remain supported for the fixture CLI.

Normal richer observations use revision manifest schema 3. Its `sourceHash` covers the serialized complete observation; a separate `snapshotHash` covers its snapshot component. Property-only changes therefore receive distinct content hashes even when all snapshot fields match. The manifest validates both hashes and the duplicate snapshot binding. Immutable manifest schemas 1 and 2 retain their original hash meanings and remain readable.

Parent comparison also reads the validated result supplement from older portable trial audits when available. It compares returned documented property values, effect catalogue/slot fields, track enabled/locked states and active-timeline context. Equivalent enumeration and decimal spellings, including signed zero, do not create history differences; distinct represented decimal values are compared without rounding through a JavaScript number. An absent key is unobserved. If either parent lacks comparable coverage, the interface says so and does not invent property changes or claim those values were unchanged. Filters apply before the 100-row display limit.

The native run recorded in `normal-property-history-live-observation.json` used the ordinary capture controls on `Frameline Restore Probe`. Each richer capture transferred in six parts and verified 43 keys/443 values across 53 items, one effect and two tracks. An initial capture matching the audited head created no duplicate. A guarded test-only Pan edit to 13.25 produced revision `59796fa0-bb68-4aa8-ba58-7347d88d821a`, despite no snapshot changes. After supported restoration to 0, a fresh capture produced `90be6d7d-587f-4930-a5da-e93cab001fad`. Both snapshots hash to `e95069f3100c849def01eca67c5b0dbc53d3739bb695eb98b8e8567fde492ad1`, while their complete-observation hashes differ. The native history inspector displayed `Pan 13.25 → 0`, including after a full app restart. Repeated save created no additional revision; record bytes and the 16-record project graph were reverified. The disposable project was left restored.

The isolated browser check used the real history services and recorded fixtures at 1440, 768 and 390 pixels, with filtering and missing-parent coverage states verified. Reviewed backup transfer of schema-3 manifests is covered by service tests. This does not add full native-property coverage, persistent track/effect identity or apply support. Richer three-way review and its separate native capture-file round trip are recorded in `property-preview-live-observation.json` and described in `THREE_WAY_PREVIEW.md`.

## Legacy Python fixture path

The original Python CLI prototype remains available for disposable fake-Resolve tests. Run `node phase-0/companion-capture.js prepare PRIVATE_DIRECTORY "Exact Resolve Project Name"`, execute its Python command inside a compatible Resolve Python Console, then run `node phase-0/companion-capture.js read PRIVATE_DIRECTORY REQUEST_ID REQUEST_SHA256`. This path is not verified in the installed Free build.

Automated tests cover request binding, private script installation, the Python fixture writer, Lua command generation, ordered Console part assembly, copied-result validation, and hash-pinned mixed live fixtures. The live checks cover audio, picture items, one simple transition, one OFX count, and a linked video/audio pair; they do not prove effect identity/settings, other transition kinds, nested sequences, or arbitrary project scale. Complete read coverage, stable export mapping, automated large-project transfer, and recoverable write transactions remain open.
