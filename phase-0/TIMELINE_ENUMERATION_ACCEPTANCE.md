# Outer timeline enumeration acceptance

The roadmap checkbox names six construct families: sequences, tracks, clips, transitions, effects and linked audio/video. This profile inventories those outer NLE constructs in the installed Resolve Free21.1.2/build21.1.20010. It does not equate that inventory with all native processing graphs or a lossless editor document.

The primary SDK exposes project timeline count/index access, typed track count/index access and timeline-item lists. Timeline items expose type, name, media-pool identity, applied `fusion`/`ofx`/`audio` effect lists and linked-item lists. Effect records expose catalogue type/name, current index and enabled state. Those current slots enumerate occurrences; neither a catalogue ID nor an index establishes persistent effect-instance identity. `MediaPoolItem.GetTimeline()` can positively identify a referenced timeline. A nil result does not exclude a compound clip, as the live negative control demonstrates; native structural inspection remains required.

Every collection and scalar read retains an explicit captured/unavailable status. Missing item, effect or link collections never become zero or empty. Sparse/unknown list keys, unknown schemas, missing metadata and inconsistent counts refuse. Frame/source placement comes from the recorded richer context, while inspector-property availability is separate from construct enumeration.

## The active-owner rule

The actual two-timeline fixture exposes a material SDK behavior: each passive whole-project scan reports six applied effects, including an apparently valid captured empty audio-effect list on the inactive timeline. The generic strict assessor therefore reports its literal lists as observed even though one Chorus is missing. Both raw observations remain unchanged as counterexample evidence.

`requireTimelineEnumerationProfile(singleDoc, nativeInventory)` is consequently diagnostic. It always reports `completeForProfile: false` and `activeOwnerCoverageRequired: true`. No operational supported path may promote one passive whole-project observation, even when every read is captured and every count agrees with its richer context.

`assembleActiveTimelineEnumeration({observations, nativeInventories})` requires a captured active-owner context for every enumerated timeline. It reconciles whole-project structural membership against the saved native structure in every context, requires stable structural projections across the interval, and takes each timeline's effect/link inventory only from the document where that timeline was active. Unavailable owner reads refuse. Off-owner empty, unavailable or differing effect/link reads remain explicit diagnostics and never supply absence or replacement values. Duplicate owner contexts must agree.

The assembled object retains each selected typed timeline and its source canonical hash, active timeline ID and page. It creates no merged ordinary schema2 richer observation under a fictitious single active timeline. The API effect/link inventory is a sequential owner-context union, not an atomic whole-project snapshot. Saved native structural membership and owner API metadata have distinct provenance. Source-bound checkpoint readers must separately verify actual save/close/load, native export, context selection/restoration and source/result integrity.

## Native closed-world membership

The new read-only native inventory supplies explicit project/timeline/sequence/container/track/item membership and media references. The profile requires complete UUID/type/current-track coverage, empty tracks, ordinary item names and native durations. At the verified zero-start fixture origins, native/API start/end coordinates must match exactly. Nonzero origins retain `timing-origin-not-calibrated` metadata without guessing an offset or promoting placement semantics. API media-pool IDs join the observed native media-pool `DbId`; `UniqueMediaPoolItemId` remains separate. Native media object kind does not determine which AV channel is used by a timeline item.

Transition membership joins by UUID, type, track and timing. Native transition `Name` is a generic label and is not coerced into API display name `Cross Dissolve`. The native source retains that raw-name hash. The API and known transition constructor provide display-type evidence.

Native effect and link payloads are opaque, including when their text is empty. `nativeEffectCount` and `nativeLinkedEdgeCount` remain null. Recognized auxiliary composition tables retain owner IDs and opaque payload hashes; they are not inferred effect counts or proofs of Fusion compositions. API-associated composition count/name reads retain their separate coverage. Internal Color/Fusion graph tools, graph parameters, retime semantics and opaque payload preservation remain outside this six-family profile.

Nested/timeline references, generators, subtitle/geometry tracks, layered/unknown native layouts, dangling references and ambiguous ownership refuse the supported profile. This is an explicit boundary, not permission to drop those objects from a purported complete inventory.

## Finite proof and controls

The baseline has two timelines, repeated media, empty duplicate-name AV tracks, real AV clips, Cross Dissolves and reciprocal AV links. Each timeline has positive applied Fusion, OFX and audio effects. Two same-catalogue Gaussian slots must remain distinct. Captures with both timelines active independently expose the passive-audio defect and verify the owner union of all seven applied slots.

The change control substitutes an OFX catalogue type at the same current slot/count, replaces a transition with a fresh occurrence while retaining its count, changes linked AV endpoints while retaining the directed-edge count, and adds a held-out timeline with fresh video/audio occurrences. `compareActiveTimelineEnumerations` and `validateEnumerationChallenge` recompute those changes from complete owner assemblies. Restoration may recreate a transition with a new UUID; it is declared construct restoration rather than original-identity or native-byte restoration.

Thirteen acceptance tests cover strict missing reads, closed reciprocal links, duplicate catalogue slots, repeated media, active-owner selection, passive silent-empty audio, unavailable off-owner reads, source drift, unsupported structures, exact zero-origin timing, uncalibrated nonzero origins and observed audio subtype codes0/1 without guessing channel semantics. The [closure auditor](timeline-enumeration-evidence-audit.js) also recomputes actual source-bound positive/change/restoration and unsupported-content evidence from the [retained public bundle](timeline-enumeration-evidence/receipt.json). Its twelve closure, diagnostic-reader and compound-boundary tests cover tampering, changed represented fields, replaced native identities, reused transition IDs, missing collections and broken compound references. All outputs keep ordinary Apply, full editor enumeration, internal graphs and lossless preservation false.
