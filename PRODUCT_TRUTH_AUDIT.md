# Product truth audit

The current desktop has four primary views: Review/Scan, Resolve preview, History, and Project media. The audit also covers the service/account/asset workflows embedded in those views. The delivered product distinguishes demonstration data, selected source observations, unavailable reads, unchecked media, last-known service data, and unsupported writes at the point of use.

| Workflow | Truth boundary and verification |
|---|---|
| Sample Review | A content-adjacent **Sample comparison** explanation identifies illustrative proposed edits, conflicts, footage and timing. Sample destination controls do not run a pull; their old claim that project parsing did not exist was corrected. Ordinary Pull remains disabled. |
| Sample History | **Sample local revision history** identifies the example local list’s demonstration messages, branches, dates and authors; service panels keep their independent selected scope. No selected project is inferred from that data. |
| Sample Media | **Sample media inventory** identifies the example media table’s demonstration names/availability; service asset controls retain their independent linked scope. It does not claim that a collaborator’s media was located. |
| Selected FCPXML | **Read-only FCPXML scan** identifies the bounded top-level picture inventory and unresolved clip identity. Selected-but-failed scans show unavailable inventory, not sample replacement. |
| Local media checks | The headline distinguishes available local files, missing files, external/unchecked references, unspecified sources, and uncheckable references. Results describe the last scan; there is no implied upload or relink. |
| Local history | The selected branch shows actual saved revision count, including a real zero. Unknown count is unavailable rather than zero. Frame rate defaults to unknown and any non-drop conversion is explicitly a user-selected display rate. |
| Resolve review | The source explanation identifies captured observations, with separate service-history provenance where applicable. **Matching observations** replaces the misleading **Already applied** presentation label. A null captured field displays **Not observed**, while entity deletion displays **Not present in this cut**. A retained FCPXML error is explicitly prefixed **FCPXML export:** so it cannot be mistaken for a failure of an independent Resolve review. Neither matching values nor review choices claim complete state or a successful apply. |
| Service status | Disconnected data does not imply a connection. Offline state is explicitly last-successful-check data. Connected state refers to the selected service scope and does not imply media availability. Unknown connection status is unavailable. |
| Asset storage/availability | Unloaded usage remains **Not loaded**; unknown byte counts remain **Size not known yet**. Published, archived, excluded and not-on-service states remain distinct. Archive retains bytes, and unavailable/excluded/archived data does not silently become downloadable. |
| Review-copy, audit and jobs | Existing controls retain read-only copy/audit wording, source fingerprints, historical timestamps, cancellation/restart status, and explicit unavailable applies. A copied export is not presented as a merged editor project. |
| Comments, approvals, templates and notifications | The existing scoped panels retain signed-out/empty states and explicit service provenance. A saved observation, approved service head, template-created empty service project, or notification is not labeled an applied editor revision. Their existing HTTPS/controller tests continue to enforce those scopes. |

The new source explanation contains no source paths, credentials, file bytes or copied project names. It derives source kind and service provenance from the current renderer state. Diagnostics retain their separate strict allowlist and review flow.

`npm test` includes pure source-state and editor-decision tests. `node scripts/verify-product-truth.cjs` runs the shipped main process/preload/renderer with disposable FCPXML/capture files and fixture OS picker results; explicit connected/offline/asset presentation fixtures exercise renderer labels without claiming a real external service connection. It checks all four views, scan failure, missing/external/unknown media, unknown field values, disabled ordinary writes, and narrow/desktop layout. Scope and observations are recorded under `phase-0/product-truth-desktop/`.
