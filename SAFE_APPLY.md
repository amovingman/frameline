# Safe Apply: supported local workflow

Safe Apply is complete for one reviewed **existing video clip Name** change on the owner's installed Resolve Free 21.1.2, build 21.1.20010, on macOS. The local runtime requires `python3` for the shipped SQLite helpers and fails closed if it is unavailable. The selected project must be at the root of a uniquely configured local disk library. The adapter refuses other operations, richer property reviews, service-history reviews, unsupported versions, extra project files, ambiguous identities and unsupported metadata.

In Resolve preview, load the base, local and incoming snapshots and finish all conflict choices. Choose **Apply reviewed rename**, quit Resolve, then choose the matching `Project.db` and prepare. Review the exact old and new name before **Back up and apply rename**.

The main process rechecks the reviewed bytes, decisions, complete native database census, project/timeline/item/track/sequence UUID joins and current source identity. It creates and fsyncs a private byte-identical restore point, prepares a separate candidate with one stale-checked SQL Name edit, and compares every persistent typed cell, schema object and application pragma with no column exclusions (9,788 cells across 146 tables in the native fixture). Physical SQLite extensions outside the supported profile are refused. Publication stages on the same filesystem, preserves permissions, ownership and all extended attributes, rechecks that Resolve is absent, atomically replaces the file, and verifies the published result.

Open that project in Resolve. Run the named script under **Workspace → Scripts** (Utility scripts appear directly in this build's menu). While it waits, click **Read Resolve check** in Frameline. The host verifies the configured library, Resolve process/start time, actual open database path/device/inode and candidate bytes before admitting native ID/name reads. Quit Resolve without saving, then click **Finish validation**. Success requires exact candidate bytes and original metadata after closing. A content-addressed native revision, reviewed choices and proof bindings remain in the authenticated transaction journal.

**Check recovery options** reads current bytes without replaying publication. It distinguishes the original, the verified candidate and a divergent file. **Restore original** accepts only the exact candidate, requires Resolve exited, republishes the verified backup with its original metadata, and requires the same native and final closed-file validation. A failed or interrupted verification can receive a fresh one-use script while Resolve is closed; earlier attempts remain retained. **Show retained backup** reveals the verified local recovery artifact. Backups are retained after both successful Apply and restoration.

This is an owner-controlled offline workflow. Application locks serialize Frameline transactions; observations do not prove exclusion of an unrelated process starting after the final check. Concurrent external writers are outside this scope. Arbitrary timeline edits, media relinking, hosted Apply, multiple editor versions, and general SDK Save-based preservation remain unsupported.
