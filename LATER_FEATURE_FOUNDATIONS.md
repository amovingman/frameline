# Later feature gates

Most modules here remain local foundations. Protected branch review, opt-in notifications, and team templates now have integrated self-hosted workflows. Editor writes, managed delivery, and rendering controls retain their separate release gates.

| Capability | Current foundation | Required before product use |
|---|---|---|
| Protected branches | `service-branch-protection.js` persists owner policy versions, exact-head requests, independent approvals, expiry, and applied receipts in encrypted combined schema 7. Actual queued pushes are gated in the branch transaction with matching activity; desktop review and real HTTPS/browser/native checks passed. Legacy `branch-protection.js` remains a local reference. | The self-hosted metadata feature is complete; managed deployment, physical cross-device operation, and editor writes remain separate gates. See [branch approvals](COLLABORATION_FOUNDATIONS.md#branch-approvals-on-a-self-hosted-service). |
| Notification preferences | `service-notifications.js` persists recipient-owned project preferences, consent epochs, exact-request receipts, read receipts, and bounded leased delivery jobs in encrypted combined schema 7. The desktop provides an account inbox and per-project off/immediate/daily UTC controls. An optional self-hosted worker submits counts-only mail over certificate-verified implicit TLS, with project unsubscribe and account-wide stop. `notification-preferences.js` remains a local planner. | The self-hosted feature is implemented; operator SMTP configuration, real-provider delivery, physical cross-device operation, queue retention/production monitoring, and managed hosting require separate validation. See [activity](PROJECT_ACTIVITY.md) and [hosting](SERVICE_HOST.md). |
| Project presets | `service-project-presets.js` saves versioned team templates and atomically creates a new empty service project, its branches/access, immutable initial media policy, and exact creation receipt in combined encrypted schema 7. A reviewed desktop flow and durable account-scoped retry journal protect saves and creations. Legacy `project-presets.js` remains a local planner. | The self-hosted branch/media setup workflow is implemented; it creates no editor file or media bytes. Managed deployment, production retention, and physical cross-device validation remain separate. See [team templates](COLLABORATION_FOUNDATIONS.md#team-templates). |
| Studio storage | `desktop-shared-storage.js`, its private registry, and History's Studio storage panel provide twenty local features: selected-folder registration, conservative identity/reconnection, source-bound requests, streamed cancellation, restart reports, interrupted checks, filtering, and reviewed path-free proposal export. `shared-storage-candidate.js` remains the earlier single-file reference. See [scope and checklist](STUDIO_STORAGE.md). | Actual studio mount/permission/disconnection evidence, portable volume identity, canonical revision/media binding, and editor relinking. | Asset lifecycle | `asset-lifecycle-policy.js` plans deletion against retained revisions, shared assets, and manual holds. It performs no deletion. | Durable holds, multi-project enforcement, retention deadlines, audit trail, owner confirmation, and transactional garbage collection. |

| Cloud rendering | `later-feature-gates.js` requires opt-in, media rights, processor contract, region, cost limit, and output provenance. | Separate product scope, security review, user consent, and cost/rights controls. The gate never sends media. |

## Cross-cutting evidence

- **Data safety:** existing immutable revision records, verified backups, atomic metadata writes, and restore tests remain the base. New branch approvals recheck reviewer access and head state; lifecycle holds only produce deletion plans. Hosted durability and end-to-end restore drills remain open.
- **Correctness:** `resolve-anchor-evidence.js` validates the exact source-bound Resolve snapshot hash before recognizing a clip ID or bounded frame range. It does not infer identity from a name or position. FCPXML clip identity is still unresolved; the compatibility corpus remains the read-only regression gate.
- **Honesty:** the desktop media summary now separates local, missing, external unchecked, unspecified, and inaccessible references. Sample timeline and media remain labeled. Unsupported apply and pull controls remain disabled.
